## R1 复盘面板进页面（先做，收益最直接）

把 `explain()` 的输出搬到对局页右侧第四个页签：走一盘 → 点"复盘" → 后台按 `analyzeTurns` 批量算 → 逐点出句子，每句话旁边挂它引用的字段（点开能看原始数字）。

判据：Playwright 跑完一盘，点复盘，页面上出现"第 N 手 X：亏 Ypp（A% → B%）"，且 `audit()` 在前端同样通过（指针解析不到就把那句标灰而不是显示）。

## R2 比赛模式收尾（S2 真正的验收）

- 读秒：主时间耗尽→进入读秒→用尽判负，走 bridge 权威时钟
- 超时判负在页面上真的发生（不是只测纯函数）
- 不限时档"持续加算 + 随时采纳"实测一遍（现在只有代码路径，没跑过一整手）
- 认输/双虚着/判和都写进记录

判据：Playwright 断言三件事——快棋档把主时间烧光后页面出现"超时判负"；读秒档 period 数递减到 0 判负；不限时档点"采纳当前着法"后引擎在 1 秒内落子。

## R3 终局数子（当前是错的，必须补）

现在 `scoreArea()` 在**没有死子标记**的情况下直接数，双虚着后给出的结果对真实对局是错的。补两条路：① 手动点死子；② 用 KataGo 的 ownership 自动提建议（它给归属，人确认）。中国规则数子，死子不清空就是错数。

判据：造三个终局形状（点眼活、双活、包围死子），自动判定与手标结果一致；`summary.userStonesLost` 与提子计数对得上。

## R4 五子棋（第 4 个游戏，也是最便宜的一个）

**为什么它最便宜**：五子棋不需要神经网络。15×15 上 alpha-beta + 增量评估（或 PBC 求解器）在笔记本 CPU 上就能到"人类基本赢不了"，一手 0.1–1 秒。也就是说这是四个游戏里唯一**不需要本机 GPU 也真·拉满**的。

接法：只写一个 `GameAdapter`（`packages/core/src/gomoku/`）+ 一个 `EngineBackend`（`packages/engine/src/gomoku-search.ts`，纯 TS alpha-beta，跑在浏览器 worker 里，**不需要桥**），其余（树、变着、棋钟、记录、解读器、复盘面板）全部复用。

规则上必须自己选的三件事（这些就是最容易留的"尾巴"）：
1. **禁手**：黑棋三三/四四/长连禁手（连珠规则）还是无禁手？无禁手下先手必胜，"满强度"就没意义 → 建议默认连珠禁手，UI 上可切无禁手
2. 棋盘 15×15 还是 19×19
3. 开局规则：直打/平衡开局（swap），否则先手优势无法消除

判据：① 必胜/必败形状的单测（活三、冲四、VCF 序列）；② 禁手判定表驱动测试；③ 引擎自对弈 20 盘，黑必输或白必胜的比例符合已知结论（无禁手先手必胜）；④ 与它下 20 手，页面不卡（一手 < 1 秒）。

**关于你那个没做完的五子棋**：本机搜遍了没有（见上），所以要么你告诉我它在哪（别的机器？别的账号的仓库？某个 `.zip`？某个在线工具里？），我把它按上面的接缝折进来；要么我按 R4 直接新写——**新写比找回更省事**，因为它不需要引擎下载，一天能出可玩版本。

## R5 提问与推演闭环

页面开一个提问入口，LLM 只能调这些只读工具：`analyze_position` / `evaluate_move` / `search_line` / `counterfactual`（已有）/ `legal_moves` / `get_packet`。每次工具调用在界面上渲染成可见的参数 chip，回答里每句话仍走 `audit()`。比赛模式禁用。

判据：问"我第 13 手为什么不行"，回答里每个数字都能在 packet 里找到；问一个 packet 里没有的事实，它必须回答"数据不足"而不是编。

## R6 国际象棋

`chess.js` + 原生 Stockfish（桥）+ 浏览器 `stockfish-19-lite.wasm` 降级档。PGN 导入导出、Lichess 云评做 fixture。判据：perft 深度 6 命中公开值；两个档各下一盘；降级档的 `StrengthBadge` 不许出现"最强"。

## R7 中国象棋

Pikafish 原生（桥），浏览器档只有 Fairy-Stockfish wasm（明显弱，必须如实标）。走法生成库先过 perft 闸门，不过就自写。中文着法（炮二平五）双向解析 + xqbase 棋谱。判据：象棋 perft d5/d6 命中；中文着法 200 局往返一致。

## R8 云同步（单人私有）

只同步着法/注解/复盘报告/对话，分析包留本地。一个长效口令，不建注册。判据：两台设备双向合并后棋谱一致，网络请求体 < 2MB。

## 已知技术债（不藏着）

1. `analyzeTurns` 批量复盘已实测但**页面没用**——现在复盘是一点一点问，冷启动一盘 1–2 分钟，改成批量能压到 20 秒内
2. 解读器阈值（4/8/15pp）是拍的，没跟人类段位对齐过
3. 120 visits 的复盘有 ±1~2pp 噪声；要下结论得 `--visits 300`
4. 比赛模式下用户那手的基准线靠"额外强制搜索"补，每手多约 2 秒（可关）
5. 桥无优先级队列（提问会排在复盘预取后面），只有 FIFO
6. 没有 LICENSE 文件；commit 未签名
7. `packet.ts` 的 `tactics` 恒为空数组——atari/切断的战术标注还没做，所以解读器不敢说"因为这手被打吃"

## 建议顺序

R1 → R2 → R4（五子棋，快且能立刻多一个可玩项目）→ R3 → R5 → R6 → R7 → R8。

理由：R1/R2 把手上的东西变成"真能用"，R4 是投入产出比最高的一块（不需要下载任何引擎、不需要桥、纯 TS，一天可玩），R3 是正确性问题但只影响终局那一步的计数。
